# 翻译是怎么做的

> 这一栏只做「中文自然语言 → 英文自然语言」，散装标签交给中栏。

## 为什么中文必须翻成英文

Anima 的文本编码器是 **Qwen3-0.6B**。T5-XXL 的**分词器**在跑，但它不加载权重——只负责给出 token 位置，DiT 内部一个 6 层的 adapter 把 Qwen 的隐状态交叉注意力到 T5 词表索引的嵌入上。

而实测 Anima 自带的 T5 分词器：**32100 个 piece 里 CJK 字符数为 0**。51 个常用汉字里 **49 个直接塌成 `<unk>`**，整句中文只有 **33–45%** 的位置是有效 token。

作者本人的说法（HF 讨论区 #52）：

> "T5 wasn't trained on Chinese. The base Cosmos2 model with T5 has no ability to understand Chinese. This, combined with the fact that all captions are in English, is why the model only understands English."

**所以中文必须翻成英文，这不是选择。**

## 配置模型接口

翻译和「模型补译」都走**设置 → 模型接口**，填三样东西：

| 字段 | 说明 |
|---|---|
| 接口地址 | OpenAI 兼容的 base url，**要含 `/v1`**，例如 `http://127.0.0.1:8080/v1` |
| 模型名 | 可下拉选择，也可直接键入 |
| API Key | 本地 llama-server 留空即可；用 Windows DPAPI 加密存放 |

**模型名那一栏可以从服务端拉取**：点「获取列表」，或点「测试连接」（两者都会请求 `GET /models`，不必点两次）。

服务端报什么就列什么。llama-server 除模型名外还会带上**量化级别、上下文长度、模型体积**，这些写在下面那行提示里：

```text
服务端列出 1 个模型。当前「qwen3-8b」：Q4_K - Medium · 上下文 40960 · 4.68 GB
```

三条刻意的行为：

- **刷新列表不会清掉你已经填好的名字。**
- **只在「服务端恰好报了一个模型」且「模型名还是空的」时才代填。** 多个模型时代选第一个纯属乱猜。
- **名字不在列表里不算错误**，只提示一句，照常可以保存。别名、自定义名，以及**根本不实现 `/models` 的网关**都属于这种情况——所以这个接口只在你想用的时候才用，不点它一切照旧。

## 翻译流程

1. 从词库给模型一份**中文词 → 英文单词**的对照
2. 模型输出英文自然语言
3. 检查是否残留中文，有则重试

第 1 步不能省。人称词（「少女」「少年」「女孩」…）在整个词库里**没有条目**——它们对应的标签是 `1girl` 这类数量词，不是词对词翻译。不给译法，8B 会稳定产出：

```text
A silver-haired少女 stands in the cherry blossoms...
```

「少女」被当成名字的一部分不翻了。而这句话在 T5 里等于没写。

> 实测对照：笼统要求"全部用英文"**无效**、降 temperature **无效**、**点名那几个字并给出译法有效**。加了对照后，同样 4 段中文从 2/4 残留降到 **0/4**。

## 追加还是替换

- **默认**：译文追加到提示词末尾（官方写法：标签 + 句号 + 散文）
- 勾选「替换已有散文」：只替换掉原来那段散文，标签不动

翻译后可以用「工具 → 撤销上次翻译」回退。

## 提示词长度

**推理端不截断**：512 在推理时只是补齐下限，两个分词器都不设上限。

但实际可用长度约 **2400 字符 / 400 词**（约 512 个 T5 token）。官方自己的 caption 变体都是 T5 形状的，超出这个范围属于训练分布之外。

> 这与**训练侧**相反：训练器在 512 token 处强制截断且不报错，写训练集时按硬上限对待
> （见 [标签还是自然语言](09-tags-vs-prose.md)）。

## 模型补译（标签的中文释义）

中栏标签右栏的中文来自词库。**词库不是全集**——实测一份 50 余张的训练集，扣掉控制词后仍有约 **93 个不同标签（147 个实例）**查不到中文，主要两类：

- **Anima 原生标签**：`cat smile`、`ass grab`、`topless`、`vertical stripes`（Danbooru 上没有，Anima 索引里有）
- **颜色+名词的复合词**：`white back bow`、`white maid headdress`、`red and white striped`

这些可以右键 → **「模型翻译（补中文释义）」**让模型补一个（快捷键 `Ctrl+Shift+T`）。用法要点：

- **只对缺中文的标签生效**。词库已有官方释义时该项会变灰——再让模型译一遍只会多一个可能更差的版本。
- **模型自己决定要不要联网查**。它知道就直接答（约 5 token），不确定才发起 `web_search`（约 487 token）。一律强制先搜反而更慢、更容易被无关结果带偏。
- **结果是推断，不是官方释义**。界面上用橙色 + `≈` 前缀 + 「模型译 · 非官方」标出，**不写回词库、不覆盖官方值**。
- 模型不确定时会**弃权**（答 `UNKNOWN`），不留半条记录。这是刻意的：错译会污染训练集，宁可少一条。
- 结果缓存在 `%LocalAppData%\AnimaCaptioner\model-gloss.json`，重开程序仍有效。

> 顺带一条：**档位不影响联网搜索**——搜索那一路按自己的需要决定，不跟全局走。

### 思考链：可以开，但思考内容永不进译文

设置里的「**推理档位**」控制的是短任务（标签释义）与散文翻译各要想多久。**散文翻译开思考与关思考都行**——同一提示词、同一模型、各 3 次采样：

| 输入 | 开思考 | 关思考 |
|---|---|---|
| 一句短描述 | 3/3 干净，5.1–5.5 s | 3/3 干净，**0.3 s** |
| 六件事的长描述 | 3/3 干净，8.8–12.4 s | 3/3 干净，**0.8–1.0 s** |

（「干净」= 不夹中文、不编造输入里没有的细节、不丢方向词。）也就是说思考对这个任务**没有可测的质量收益，只是慢 10–15 倍**。默认的「关闭思考」是最省的选择；想让它多想一会儿，选任一档位即可，不会有副作用——下面两条保证它污染不了结果。

档位一共九项：**自动**（不下发，由服务端按自己的默认档决定）、**关闭思考**，以及 `minimal`→`max` 七档强度。选完之后，下面那行提示会**如实告诉你这一档会不会真的发出去**——因为能不能下发取决于服务端，而"选了一个不生效的档位"本身是看不出来的。两种服务端的差别也由程序自动处理：本地 llama-server 只认「关闭思考」这一档（它用 `enable_thinking=false` 关，没有强度可调），云端用 `reasoning_effort`。

**1. 思考内容永远不进译文。** 程序只取答案，思考过程会被剥掉；遇到**只有思考、没有答案**的情况一律如实报错，绝不把思考当译文——思考可能被截断在半个句子上，而且是模型的自言自语（「好的，用户让我翻译……」）。

**2. 只要会思考，程序就自动给思考留 token 余量。** 「最大 token」是「思考 + 答案」的**总**预算，不是答案自己的。所以程序会在你设的额度之上再加一段思考余量，让你设的额度仍然完整地留给答案。实测：预算 400 时思考就吃光了、答案一个字都没写；加上余量后正常（答案 234 字符，思考另算）。档位越高思考越长，如果仍然撞上截断，界面会提示调大「最大 token」。

**3. 一个例外：AI 助手里带工具的轮次始终保留思考。** 实测关掉思考后模型就不再发出工具调用，搜索工具会直接失效（见 [AI 助手](12-ai-assistant.md)）。所以那一路不跟档位走。
