# 标签顺序与分段

> 官方只强制六**大类**的顺序；同一大类内部顺序任意，本工具不做任何重排。

## 官方规定的顺序

模型卡 "Tag order" 一节给的顺序是：

```text
[quality/meta/year/safety tags] [1girl/1boy/1other etc]
[character] [series] [artist] [general tags]
```

紧接着一句是关键：

> "Within each tag section, the tags can be in **arbitrary order**."

所以本工具的做法是：**只固定大类之间，段内顺序原样保留**。上移 / 下移和拖拽都**只在本段内生效**，跨段拖动会被拨回本段。

## 第一段为什么拆成四段

官方把 `quality/meta/year/safety` 写成**同一个方括号**，所以它们既不是"官方要求分开"、也不是"必须合并"——方括号只是成员清单，配合 `arbitrary order` 那句话，怎么排都是合规的。

本工具选择**拆成四段**（质量 / 元信息 / 年代 / 安全），子序按官方那行的写法：

```text
[质量] [元信息] [年代] [安全] [人物数量] [角色] [作品] [画师] [一般标签]
```

理由：

- 安全词有**独立于词库的档位校验**（见 [安全标签的边界](08-safety-ratings.md)），单独成段才能一眼看出"这个段里哪个是安全词"；
- 官方自己的推荐前缀是 `masterpiece, best quality, score_7, safe`，正好是 **质量 → 安全** 这个子序；
- 四类的判据来源不同（质量/元信息来自模型卡逐条列举，安全来自 Danbooru 评级规范），耦合在一段里改一处会牵动另一处。

> ⚠️ 官方模型卡**自己前后不一致**：`## Tag order` 写 `quality/meta/year/safety`，
> 而 `## Full tag example` 的开头是 `year 2025, newest, normal quality, score_5, highres, safe`
> —— 年代排在质量前面。既然 `arbitrary order` 授权自定，本工具按 `Tag order` 那一行，
> 与官方推荐前缀保持一致。

**这个改动不动已有标注。** 实测本训练集 53 个 caption 里除安全词外**没有任何**控制词
（质量 / 元信息 / 年代都是 0 个），而安全词在旧方案（合并段）和新方案里都排在第一位，
所以拆分对现有文件是**逐字节恒等**——`sections` 回归的「53/53 恒等」仍然成立。

## 中栏的分段显示

中栏按这个顺序分段，每段一个该类别颜色的框，段头显示这一段的名称和标签数。

加标签时（中栏顶部输入框，中文或英文都行）会自动落到它所属的段里，而不是甩到列表末尾。

保存前若想整体规整一次，用「标签 → 规整大类顺序」（`Ctrl+Shift+S`）。

## 关于"一般标签内部顺序"

网上流传着一些更细的顺序建议（例如「头发 → 眼睛 → 服装 → 姿势」），但：

- 官方**没有**这个规定，只说段内任意
- 模型卡自己的 `## Full tag example` **并不遵守**任何细粒度顺序——头发、服装、表情来回穿插了三轮
- 那些建议来自生态里的排序工具，各家分类互不相同，是项目约定而非规范

所以本工具**不**对一般标签做子排序。你的段内顺序就是最终顺序。

> 有一条例外是有实证支撑的：**分隔符必须用 `", "`（逗号 + 空格）**。Qwen 词表里存在 `",a"` 这样的 token，不加空格会明显改变分词，标签效果会下降。这一条是实打实的影响，与顺序无关。

## 文件里的顺序可能和显示的不一样

中栏是按大类**重新排好**显示的，但 `.txt` 里的实际顺序可能不是这样。两者不一致时，中栏上方会显示一条提示：

> ⚠ 文件里的大类顺序不规范（N 处跨段）

这时定稿状态以**提示词原文那份**为准（那才是实际写进文件的内容）。点提示里的按钮或按 `Ctrl+Shift+S` 可以一键规整。
